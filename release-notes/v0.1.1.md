# vmemo v0.1.1

## English

`vmemo` v0.1.1 is a distribution release. The read-only command surface (`list`, `search`, `show`, `export`, `doctor`) and the production data contract - macOS 26 with Voice Memos build 1380, failing closed everywhere else - are unchanged from v0.1.0.

The release channel moves from a Developer ID Installer signed PKG at `/usr/local/bin/vmemo` to an Apple-notarized universal2 ZIP installed by a version-pinned script at `~/.local/bin/vmemo`, without sudo. The immutable v0.1.1 GitHub Release carries `vmemo-0.1.1-macos-universal2.zip`, whose only payload entry is `vmemo-0.1.1-macos-universal2/vmemo`, together with `SHA256SUMS` and `provenance.json`, which record the artifact name, version, code-signing identifier, install path, deployment target, architectures, source revision, and the Swift and SDK versions used for the build.

```sh
curl -fsSL https://raw.githubusercontent.com/patrick-fu/voice-memos-cli/v0.1.1/install.sh | sh
```

`install.sh` writes only after every check passes: the release is immutable, the archive matches `SHA256SUMS`, the ZIP has exactly the expected structure, the executable verifies strictly as `Developer ID Application` signed for `com.paaatrick.voice-memos-cli` with a secure timestamp and Hardened Runtime and passes an online `spctl` assessment, the binary contains both `arm64` and `x86_64` slices, and the reported version matches the provenance record. The binary is then replaced atomically inside the destination directory. `VMEMO_INSTALL_DIR` and `VMEMO_VERSION` override the directory and version, and if `~/.local/bin` is missing from `PATH` the script reports how to add it without editing shell configuration.

A bare executable inside a ZIP cannot carry a stapled ticket, so notarization is verified against Apple's online ticket and the first Gatekeeper check needs network access. Signing and notarization grant no macOS permissions: reading Voice Memos may still require the user to grant library access, and `vmemo doctor` reports the current state.

The published v0.1.0 PKG release stays immutable and untouched; v0.1.1 only adds a new tag with its own assets.

## 中文

`vmemo` v0.1.1 是一次发布渠道更新。只读命令面（`list`、`search`、`show`、`export`、`doctor`）以及生产数据契约——仅支持 macOS 26 与 Voice Memos build 1380，其他环境 fail closed——与 v0.1.0 完全一致。

发布渠道从装在 `/usr/local/bin/vmemo` 的 Developer ID Installer 签名 PKG，改为由固定版本脚本安装到 `~/.local/bin/vmemo` 的 Apple 公证 universal2 ZIP，全程不需要 sudo。不可变的 v0.1.1 GitHub Release 包含 `vmemo-0.1.1-macos-universal2.zip`（ZIP 内唯一载荷条目为 `vmemo-0.1.1-macos-universal2/vmemo`）、`SHA256SUMS` 与 `provenance.json`；后者记录产物名称、版本、签名 identifier、安装路径、deployment target、架构、源码 revision 以及构建使用的 Swift 与 SDK 版本。

```sh
curl -fsSL https://raw.githubusercontent.com/patrick-fu/voice-memos-cli/v0.1.1/install.sh | sh
```

`install.sh` 只在全部校验通过后才写入：Release 已标记不可变、压缩包与 `SHA256SUMS` 匹配、ZIP 结构精确符合预期、可执行文件通过严格校验（由 `Developer ID Application` 为 `com.paaatrick.voice-memos-cli` 签名，具备安全时间戳与 Hardened Runtime，并在线通过 `spctl`）、包含 `arm64` 与 `x86_64` 两个 slice，且报告的版本与 provenance 记录一致。随后在目标目录内原子替换二进制文件。`VMEMO_INSTALL_DIR` 与 `VMEMO_VERSION` 分别覆盖安装目录和版本；若 `PATH` 中没有 `~/.local/bin`，脚本只提示应添加的 PATH 命令，不修改 shell 配置。

ZIP 中的裸可执行文件无法 staple 公证票据，因此公证状态需向 Apple 在线校验，首次 Gatekeeper 检查需要网络。签名与公证不授予任何 macOS 权限：读取语音备忘录仍可能要求用户亲自授予资料库访问权限，`vmemo doctor` 会报告当前状态。

已发布的 v0.1.0 PKG 保持不可变、不做改动；v0.1.1 只新增一个 tag 及其自身资产。
