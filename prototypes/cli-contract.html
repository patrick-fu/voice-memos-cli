A · 资源 / 子命令式

vmemo recordings …

把录音视作唯一资源；help 像可导航的 API 目录。最接近常见 CLI 与 REST 的心智模型。

候选：Unix 可读性优先

root help · 机器与人共用入口

Usage: vmemo recordings <command> [options]

Commands:  list  search  show  export  rename  delete
Global:    --json  --quiet  --version  --help
Contract:  stdout=结果；stderr=诊断；exit=稳定分类。recording-id 是不透明值。

典型 command help

Usage: vmemo recordings export <recording-id>
  --to <directory>       required, user-selected destination
  --format original      only supported v0.1 value
  --json                 result envelope, no title by default
  --dry-run              validate selection + destination; write nothing

EXIT: 0 exported | 2 usage | 3 denied | 4 unsupported | 5 partial | 6 unavailable

稳定 identifier + 默认隐私

rec_01J…
CLI 暴露的不透明 ID；adapter scope + schema version 绑定。绝不把路径、文件名、Z_PK 或标题当 selector。
默认输出
id、date、duration、availability、backend。标题为 <redacted>；仅显式 show --include title 才返回。

全部资源命令：每个动词一条窄且可组合的语法

listvmemo recordings list --limit 20 --json

游标分页；成功结果写 stdout。

searchvmemo recordings search --created-after 2026-08-01 --json

仅 filter allowlist；不把 Voice Memos UI search 冒充 records API。

showvmemo recordings show rec_01J… --json

单条 metadata；--include title 必须显式。

exportvmemo recordings export rec_01J… --to ./out --dry-run

验证来源、目标与快照稳定；复制才返回路径。

renamevmemo recordings rename rec_01J… --title "…" --confirm tok_… --yes

v0.1 不支持 可保留 help，执行一律拒绝；不能写私有 DB。

deletevmemo recordings delete --id rec_A --id rec_B --dry-run

v0.1 不支持 不删除文件；批量也不改变该边界。

人类 vs --json

$ vmemo recordings list
ID          DATE        DURATION  TITLE
rec_01J…    2026-08-21  04:32     <redacted>

$ vmemo recordings list --json
{"schema":"vmemo.recordings.v1","items":[{"id":"rec_01J…","title":null,"titleRedacted":true}]}

A 采用 Unix：成功 body 在 stdout；失败诊断在 stderr。--json 不把 error 偷塞进成功数据流。

selection、dry-run 与 partial failure

问题A 的回答
单条 / 批量单条 positional <recording-id>；批量重复 --id 或 --from-json @file，不可混用。
破坏性预览--dry-run 返回拟执行项；真实 mutation 必须复用 confirmationToken 加 --yes。
幂等 / 部分失败读/export 可重试；逐项 status。任一失败 exit 5，stdout 仍给完成/未完成清单。

明确拒绝，而不是“神奇地能写”

stderr: vmemo: VMEMO_UNSUPPORTED_BACKEND: rename/delete require a supported public backend
hint: complete this change in Voice Memos.app; private database writes are never attempted
exit: 4

Shortcuts 只可作为用户手工 helper 的 experimental 路径：不能按 rec_… 注入实体、不能承诺 JSON 回执或无人值守确认。

一句话定位：适合把 CLI 当“资源 API”的团队：路径可预测、help 很好发现；代价是 confirmation 与 batch 规则散落在多个子命令中。
B · 扁平 verb-first

先说要做什么，再给对象。

vmemo list、vmemo export、vmemo delete 在一张操作板上对齐输入、结果和安全门。

01 · 意图（root help）

Usage: vmemo <verb> [selection] [options]

Read:    list | search | show | export
Change:  rename | delete
Inspect: doctor | help <verb>

All verbs accept: --json --help
稳定 selector

每条记录有 rec_… opaque ID；可加 --where @selection.json。title/path 只能展示，永不做匹配键。

选择先于动词

--id rec_A、重复 --id、或 --where 三选一。零条 / 多条均明确返回，不猜。

敏感字段默认

list/search 表格和 JSON 都省略 title；show --reveal title 只在本地终端输出，不进错误或诊断。

02 · 动词（典型 help 与示例）

listread

vmemo list --limit 20 · vmemo help list

searchread

vmemo search --created-after 2026-08-01 · allowlist metadata filter。

showread

vmemo show --id rec_01J… --reveal title · 单一 selection 必需。

exportread + copy

vmemo export --id rec_01J… --to ./out --dry-run · snapshot preflight。

renameunsupported

vmemo rename --id rec_01J… --title "…" --yes · v0.1 只拒绝。

deleteunsupported

vmemo delete --id rec_A --id rec_B --dry-run · 不触碰私有文件或 DB。

03 · 守卫（统一，不藏在动词里）

0 · success
所有 selected item 处于成功/已存在的幂等终态。
5 · partial
envelope 必有每项 status/code；没有“exit=0 就全成功”。
3 / 4 / 6
PERMISSION_DENIED / UNSUPPORTED_BACKEND / SOURCE_UNAVAILABLE。错误 envelope 写 stdout；stderr 只给人类单行摘要。
确认是两步 protocol

mutation 的 --dry-run 返回 confirmationToken（选择、后端、过期时间绑定）。真实请求必须带 --confirm tok_… --yes。

典型 command help

vmemo help delete
Requires: --id+ · --dry-run first · --confirm · --yes
v0.1 response: UNSUPPORTED_BACKEND, exit 4.

Shortcuts ≠ backend仅 experimental、用户手工 helper；不可按 opaque ID 精确操作，不能把 UI/Automation 提示伪装成 CLI confirmation。
一句话定位：适合 agent 以“动词 + selection + envelope”生成调用：所有动词共享 guardrails；代价是资源归属感更弱，命名空间扩张时可能拥挤。

RESPONSE · success / per-item states share one envelope

本地示例
{
  "schema": "vmemo.response.v1",
  "id": "req_01J…",
  "ok": true,
  "result": {

  "errors": []

人类仍可用：vmemo help recordings.export 输出 method schema、参数和 error codes；vmemo query --pretty 只改变空白，不改变 JSON。主契约始终是 request/response，不是表格。

schema / 识别符

recording.id
rec_… opaque、adapter-scoped；不输出也不接受路径、标题、Z_PK。
selection
{"ids":[…]} 或 {"filter":…}；必须 exactly one。单条也用同一形状。
privacy.include
默认 []；只有 ["title"] 才可在 result 中出现 title，永不放 error。
mutation protocol
dryRun:true → plan.confirmationToken → confirm:{token,yes:true}。
errors[]
{scope,code,retryable,message}；如 PERMISSION_DENIED、UNSUPPORTED_BACKEND、SOURCE_UNAVAILABLE。
batch
result.items[] 始终逐项回报；部分失败是 ok:false + PARTIAL_FAILURE，exit 3。
写能力诚实状态rename/delete 可在 schema 占位以便 client 前向兼容，但 v0.1 必返 UNSUPPORTED_BACKEND。私有写入不做；Shortcuts 仅 experimental，不能满足此 RPC 的确定性。

典型 method help + 全部语义

$ vmemo help recordings.export
params.selection: {"ids":["rec_…"]} | {"filter":…}
params.destination: user-selected directory
params.dryRun: boolean
success: result.items[].status = planned|exported|already_exists
errors: each item gets code; permission/unsupported never falls back
idempotency: request.id + destination policy; retry returns same terminal state when known

$ vmemo query < request.json  # list/search/show
$ vmemo mutate < request.json # export/rename/delete; v0.1 write methods reject

错误 response（包括权限 / unsupported）

{"schema":"vmemo.response.v1","id":"req_…","ok":false,
 "result":{"items":[{"id":"rec_A","status":"rejected","code":"UNSUPPORTED_BACKEND"}]},
 "errors":[{"scope":"request","code":"UNSUPPORTED_BACKEND","retryable":false,
 "message":"A supported public write backend is unavailable."}]}

C 的成功与失败均写 stdout JSON；stderr 仅限无法解析输入、启动失败等 transport/runtime 诊断。

一句话定位：适合 agent-first 自动化：schema、batch、confirmation 与错误都只有一种形状；代价是人类要学 JSON，临时 CLI 使用不如 A/B 轻。
